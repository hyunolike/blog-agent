## 동작과 한계

기존 BM25 + 벡터 RRF를 유지한다. 특정 기술명(예: RequiresMountsFor)이 있으면 그 용어가 없는 후보를 제거하고 조사·요청 표현의 영향은 줄인다. 벡터의 차원·유한값을 검사하고 양의 유사도만 사용한다. 숫자 오류 코드의 일부(ORA)는 전체 코드(ORA-28040)를 대신하는 개념으로 확장하지 않는다. RRF와 양의 유사도는 정답 확률이나 충분한 관련성 보증이 아니며, 외부 모델을 이용한 의미 재순위화는 추가하지 않았다.

독립된 새 질문은 이전 질문을 검색어로 합치지 않는다. '그거 더 자세히' 같은 짧고 분명한 후속 표현에만 직전 사용자 질문을 함께 쓴다. '그거 말고 낙관적 락…'처럼 새 한국어 주제를 제시한 문장은 합치지 않는다. 현재 글의 요약·본문은 '이 글', '보고 있는 글', 독립된 요약 요청일 때만 우선한다. 단어 경계를 확인해 '차이 글'을 '이 글'로 오인하지 않는다. 모호한 지시어를 모두 해결하는 질의 재작성 모델은 아니다.

단순 질문은 최소 글 수를 채우지 않고 점수순으로 글당 최대 3개·총 6개를 고른다. 목록은 최대 8개, 비교는 적합 후보에서 글을 분산한다. 문맥은 markup·escape·생략 표시·관계 증거를 모두 포함해 9,000자 이하다. 글별 첫 조각을 먼저 담고 긴 조각의 길이를 제한하며, 관계 근거가 뒤에 있으면 해당 위치 주변을 담는다. 토큰 길이와 문자 길이는 다르며 선택하지 못한 세부 내용까지 모델이 아는 것은 아니다.

비교·관계 질문에서만 최초 검색 글 중 최대 2개를 seed로 **1 hop·최대 2개 관계·총 최대 10개 조각**을 탐색한다. 새 이웃은 다시 탐색하지 않는다.

| 종류 | 근거 | 의미하지 않는 것 |
| --- | --- | --- |
| link | 양쪽 chunk ID와 원문에 있는 동일 블로그 URL. 인용 방향을 보존하고 들어오는 링크도 탐색 | 두 글의 주장 전체가 일치하거나 앞 글이 뒷 글의 원인이라는 보증 |
| series | 번호를 제외한 제목이 같은 명시적 `(1)`/`(2)`, `1편`/`2편` 제목. 양쪽 제목 기록 | 같은 카테고리·프로젝트라는 이유만으로 생기는 시리즈 |
| concept | 질문의 정확한 영문 기술명이 양쪽 원문/절에 등장. 원문 조각 및 용어 기록 | 동시 등장이나 임베딩 유사성이 인과·의존 관계라는 주장 |

수집기가 수동으로 붙인 첫 줄 `프로젝트: ...`는 일반 검색에 유지하되 원문 관계 증거에서 제외한다. 관계 검색과 문맥 절단·검증은 동일한 정확한 기술어 경계를 사용해 Redis를 redistribution의 일부로 오인하지 않는다.

최종 문맥에 양쪽 출처와 해당 근거가 남은 관계만 `<relation kind from to>`로 전달한다. `sources[].chunkId`와 `relations[]` 메타데이터에 출처 번호 연결을 보존한다. 현재 UI는 기존 인용 카드 그대로 사용한다. 모델에는 원문 사실과 비교 추론을 구분하고 양쪽 출처를 인용하며, 인과가 확인되지 않으면 모른다고 말하도록 지시한다. 이 지시는 생성 모델의 준수를 강제하는 의미 검증기가 아니다.

version 1 인덱스의 기존 URL/제목/본문으로 동작하며 인덱스 파일을 바꾸지 않는다. 기존 추출기가 제거한 내부 링크는 복구할 수 없다. 이후 정상 수집하는 글에서만 내부 글 링크를 markdown에 보존한다. 임의 재수집·운영 재색인은 하지 않는다. 한국어 개념어·자동 시리즈 감지는 보수적으로 생략하며, 의미 관계를 무리하게 추정하지 않는다.

## 재현 가능한 평가

```bash
npm test
npm run eval:grounding
NVIDIA_API_KEY='' node --import tsx eval/retrieval.ts
npm run typecheck
NEXT_TELEMETRY_DISABLED=1 npm run build
```

`eval:grounding`은 .env 파일·제공자·네트워크 없이 저장 인덱스에서 검색과 문맥 구성을 평가한다. 비교(Oracle, 런타임, Redis), 질문 전환·후속 질문, 무관한 현재 글, 현재 글 요약, 근거 없는 기술어의 8개 사례가 있다. 합격은 필요한 글이 문맥에 있고 금지 글이 없으며 관계 종류·문맥 한도가 맞다는 뜻이다. 생성 답변을 채점하지 않는다.

이전 **96%는 키워드 검색 24/25**였으며 답변 정확도가 아니다. 변경 후 같은 25개는 25/25였다. 비교 3개를 더한 현재 검색 평가는 28개 답변 가능 질문을 사용한다. 목록·관계 질문은 top-k가 가변이므로 이를 고정 recall@6라고 부르지 않는다. `expectedPostIds`는 넓은 질문의 후보/대안 목록일 수 있고, `requiredPostIds`는 해당 비교에서 모두 필요한 글이다. 명시된 필수 글은 하나라도 빠지면 실패한다. 벡터·실제 모델 성능으로 일반화하지 않는다.

실제 모델 답변 비교는 할당량·비용 및 질문/근거 전송이 있어 이번 작업에서 실행하지 않았다. 필요한 조건을 확인한 개발자가 별도로 실행한다.

```bash
# .env.local의 NVIDIA_API_KEY를 사용하고 실제 외부 API에 질문/근거를 전송한다.
npm run eval:answers -- <model> [model...]
# 답변과 sourceBlock·sources·relations를 읽고 사람이 검토한 뒤 로컬로 합친다.
npm run eval:review -- eval/results/<answers>.jsonl <human-reviews>.jsonl
```

평가 결과는 다음을 **분리**한다. 기존 autoPass는 오해를 줄이기 위해 `citationHeuristicPass`로 바꿨다.

| 축 | 자동/사람 | 판단 |
| --- | --- | --- |
| 필요한 글 누락 | 자동 | 문맥에 없는 requiredPostIds, requiredPostRecall |
| 인용 번호 유효성 | 자동 | 실제 출처 번호와 맞는가. 정답성·문장 지지를 보장하지 않는다 |
| 정답성 | 사람 | 질문에 답하는 핵심 사실·수치가 원문과 일치하고 필요한 한계를 밝혔는가 |
| 인용 지지 | 사람 | 각 주장 바로 뒤 인용의 실제 원문이 그 주장을 지지하는가. 제목/인용 번호 일치만으로 통과시키지 않는다 |
| 근거 없는 관계 | 사람 | 원문이 뒷받침하지 않는 인과·순서·의존·동일성 주장 수. 추론의 불확실성과 양쪽 근거를 검토한다 |

검토 JSONL 한 줄의 형식은 아래와 같다. 예시는 형식 안내이며 실제 답변의 평가 결과가 아니다. notes에 판단 근거·원문 위치를 남긴다. 반드시 검토한 답변 행의 `answerHash`를 복사한다. 질문·답변·sourceBlock·출처 매핑을 SHA-256으로 묶고 재검증하므로 새 실행의 다른 답변/근거에 이전 판단을 적용하면 실패한다. 같은 파일의 중복 model/id도 거부한다. 이전 형식처럼 근거·hash가 없는 결과는 이 CLI의 검토 대상이 아니다.

```json
{"model":"<실제 모델 ID>","id":"q32","answerHash":"<검토한 답변 행의 64자리 answerHash>","correctness":false,"citationSupport":false,"unsupportedRelationClaims":1,"notes":"형식 예시: 원문에 없는 인과를 단정했다면 해당 문장과 근거 위치를 기록"}
```

검토하지 않은 정답성·인용 지지·관계 주장은 `null`이다. 이를 0건/정답으로 집계하지 않는다. 실제 오답 사례를 받으면 질문, 기대 답, 실제 답, 해당 턴의 sourceBlock 및 배포 SHA를 함께 남기고 별도 회귀 사례로 추가한다. 사용자 개인정보·비밀키는 평가 파일에 넣지 않는다.

## 검토와 배포

이 변경은 PR #8과 별도 develop 기반 브랜치다. Answer evidence checks workflow는 모델 키 없이 단위/근거 평가·키워드 검색·타입·빌드를 확인한다. 기존 수집 workflow와 PR #8은 수정하지 않는다. `vercel.json`은 두 작업 브랜치만 Git 자동 배포에서 제외한다. 병합·운영 배포·Docker 실행은 이 작업 범위 밖이다.


## 독립 코드 검토에서 수정한 회귀

별도 검토자가 재현한 중요 5건을 실패 테스트로 확인한 뒤 수정했다: 한국어 주제 취소/전환, '차이 글'의 현재 글 오인, 수동 프로젝트 소속을 원문 개념 관계로 취급, 부분 문자열 때문에 정확한 증거를 잘못 자르는 문제, 다른 실행 답변에 사람 평가를 재사용하는 문제. 실제 운영 오답의 원인으로 입증된 것은 아니다.

보수적인 선택의 비용도 남는다. 정확한 기술어·짧은 후속 표현·번호 제목만 인식하므로 일부 유용한 의미 관계를 놓칠 수 있다. 관계 witness가 예산으로 빠지거나 내부 링크가 상대 URL이면 확장하지 않을 수 있다. 이런 경우 근거를 지어내지 않고 단순 검색으로 남기며, 실제 질문 사례로 다음 회귀를 보완한다.
