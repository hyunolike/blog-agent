# 근거 중심 검색·관계 확장

사용자가 승인한 범위는 답변 부정확성의 위험을 줄이는 코드·회귀 평가와 Draft PR이다. 운영 배포·재색인, Docker 조작, 새 자격 증명·외부 서비스 활성화는 제외한다. 실제 오답 사례가 없어 운영 오답의 원인이나 답변 정확도 개선율을 주장하지 않는다.

## 설계

- 기존 TypeScript, BM25 + vector RRF, version 1 JSON 인덱스를 유지한다. 새 DB/모델 호출/의존성을 추가하지 않는다.
- 질문 전환 시 이전 질문을 버리고, 명확한 지시어 후속 질문에만 이전 사용자 질문을 보탠다. 과거 답변은 검색 근거로 사용하지 않는다.
- 특정 영문 기술어가 인덱스에 존재하면 해당 기술어와 무관한 후보를 제외한다. 대화형 조사·요청 표현의 BM25 영향은 줄인다. 벡터 차원·유한값을 확인하고 양의 유사도만 순위에 넣는다. RRF 점수를 정답 확률로 해석하지 않는다.
- 단순 질문은 점수순으로 글당 최대 3개, 전체 최대 6개 조각을 선택한다. 최소 4개 글을 강제로 채우지 않는다. 목록/비교 질문은 적합 후보 안에서 글을 분산한다.
- 현재 글은 '이 글', '보고 있는 글', 독립된 요약 요청처럼 명시적인 경우에만 우선한다. 다른 질문에서는 일반 검색으로 처리한다.
- 문맥은 전체 직렬화 블록 9,000자를 넘기지 않는다. 긴 조각 하나 때문에 이후 글이 모두 누락되지 않도록 글별 1개를 우선하고 긴 조각을 제한한다. 번호는 실제 포함한 출처에만 부여한다. 원문의 source 구분자와 속성을 escape한다.
- 비교·관계 질문에만 검색된 글에서 1 hop, 최대 2개 관계를 확장한다. 링크는 원문 URL, 시리즈는 명시적 동일 시리즈/번호 제목, 개념은 질문에 등장한 정확한 영문 기술어의 양쪽 원문 출현을 근거로 한다. 카테고리·프로젝트 공통 소속이나 임베딩 유사도만으로 관계를 만들지 않는다.
- 관계 증거의 양쪽 조각을 문맥에 넣고 번호·chunk ID를 연결한다. 문맥 예산으로 한쪽이 빠지면 관계도 전달하지 않는다. 링크/시리즈/개념 등장은 인과·시간·구현 의존 관계를 보장하지 않는다. 모델에게 사실/비교 추론/모름을 구분하고 양쪽 출처를 붙이도록 지시한다.
- 기존 인덱스에 있는 URL과 제목으로 즉시 동작한다. 이후 정상 수집 때 내부 글 링크를 markdown에 보존한다. 이번 PR은 data/index.json을 변경하지 않는다.

## 평가

검색·문맥 회귀(오프라인)와 생성 답변 평가(외부 모델·사람 검토)를 분리한다. 필요한 글의 누락, 인용 번호 유효성, 정답성, 인용 내용의 실제 지지 여부, 근거 없는 관계 주장 수를 별도 필드로 기록한다. 인용 번호가 맞다는 이유로 정답성/인용 지지를 통과시키지 않는다. 24/25 키워드 검색 적중은 답변 정확도가 아니다.
